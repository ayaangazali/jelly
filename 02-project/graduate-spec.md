# GRADUATE — Product Spec

> Your agent solves the same problem for the fiftieth time and still pays frontier prices to think it through from scratch. GRADUATE watches your verified runs, trains a small model you own on the ones that passed, and routes that work to it forever after. Your test suite is the only teacher it needs.

---

## 1. The problem in plain terms

A new engineer asks how to deploy for three weeks, then stops asking. An AI agent is a new hire every single morning, forever. It re-derives the same approach, burns the same tokens, takes the same 16 turns, and you pay frontier rates for all of it.

Three things make this worse than it sounds:

1. **The repeated work is the majority of the work.** Fix a failing test, add an endpoint the way this repo adds endpoints, write a migration, update a changelog. Same shape, over and over.
2. **The fix is unavailable to most teams.** Fine-tuning needs labeled examples, and nobody has thousands of labeled examples of their own workflows. So they never fine-tune and stay on rented frontier models permanently.
3. **Caching does not solve it.** See `cost-model.md`. Caching discounts re-sent prompt prefixes within minutes. It does not reduce turns, does not touch output tokens, and expires.

## 2. The insight

**The labels already exist and they are free.** Every successful agent run in software ends with a command that returned exit code 0. That is a perfect, unambiguous, human-free judgment of correctness, and it has existed for fifty years.

Memorable already stores it. Per their site, each procedure keeps the files touched, the command that proved it worked, the order of steps, and real exit codes.

So a stream of automatically-graded attempts is already being generated by work you are already doing. That stream is:
- **Training data** for supervised fine-tuning (Idea 1)
- **A reward signal** for reinforcement learning (Idea 2)

Every company's test suite encodes what "correct" means inside that company's codebase. It is proprietary, unreplicable, and currently does nothing except turn red or green. GRADUATE turns it into an owned asset.

## 2b. The precedent (this is not speculative)

Harvey, the legal AI company, watched gross margins go from roughly 50% to roughly **-50% by June 2026** as token usage rose about twentyfold under OpenAI and Anthropic usage-based enterprise pricing (Bloomberg). In August they shipped **Harvey Tenet**, a Kimi K3 base post-trained with Fireworks via **asynchronous reinforcement learning in realistic legal work settings**. Margins turned positive again, with no reported price change.

Their reported results: cost per query down roughly **90%**, tokens in completed trajectories down **58%**, criteria pass rate up more than **15%**, intelligence-per-token 190.8 versus 129.3 for the best frontier configuration. Reporting also notes they still route the hardest matters to frontier models, which is exactly the escalation path in §4.

Harvey's stated goal includes giving law firms a path to own their own specialized models. Bloomberg named Abridge, Decagon and Ramp making similar open-weight moves, and Thomson Reuters shipped an in-house model on an open-source base in the same month.

**The gap:** Harvey spent six months of research, a Fireworks partnership, and (per one report) ~150 NVIDIA B300 GPUs over two months. Thomson Reuters reportedly spent two-plus years and ~$40M. The playbook is proven and unreachable for everyone else. GRADUATE is that move as a background process with a one-line install.

*Always attribute these numbers to Harvey and the press. Never present them as GRADUATE's results.*

## 2c. The shape: speculative decoding at the task level

Speculative decoding has a small model draft tokens and the big model verify them. GRADUATE moves that pattern up a level: the graduated model drafts the **whole task**, and the **test suite** verifies it. Accept on exit 0, escalate to the frontier model on rejection.

This is the fastest way to explain why quality doesn't collapse when you route to a small model: the small model never gets the final word. Say "verifier-gated," not "lossless" — a test suite is a weaker judge than a full model, so the equivalence guarantee of real speculative decoding does not transfer.

## 3. What GRADUATE is

A thin, drop-in layer with four parts:

| Part | Does |
|---|---|
| **Watcher** | Reads Memorable procedures and their run history. Clusters runs into task types. Counts verified successes per type. |
| **Registrar** | When a task type crosses the graduation bar, builds a dataset from its verified runs and kicks off a River training job. Tracks job state. |
| **Router** | An OpenAI-compatible proxy. Classifies each incoming request into a task type and forwards it to the graduated model if one exists, otherwise to the frontier model. |
| **Escalator** | Checks the graduated model's output. If it fails verification or the model signals low confidence, retries on the frontier model, and records that failure as a negative example. |

## 4. The graduation lifecycle

```
LEARNING      →   READY        →   TRAINING      →   GRADUATED     →   PROBATION
(<N verified      (N verified      (River job        (routed to        (a failure sent
 runs, all        runs, dataset    running)          owned model,      it back; needs
 frontier)        built)                             verified each     re-training)
                                                     time)
```

Rules:
- **Graduation bar:** N verified successes of the same task type. N = 5 for the demo. Configurable.
- **Every graduated run is still verified.** GRADUATE never trusts the small model blindly. The verify command runs regardless.
- **Failure demotes.** A graduated model that fails verification hands the task back to the frontier model, and the failure becomes a negative example for the next training round.
- **Nothing graduates without consent.** Following Memorable's fail-closed posture, no task type trains without an explicit enable.

## 5. The Idea 2 layer (Exit Code RL)

Supervised fine-tuning on winning traces is the baseline. The ambitious layer is using the exit code as a reward and letting River's RL improve the model past the traces it was given.

**Reward function, v1:**

```python
def reward(run):
    r = 1.0 if run.exit_code == 0 else 0.0
    if r == 0.0:
        # partial credit for moving in the right direction
        r = 0.3 * (run.tests_passed / max(run.tests_total, 1))
    r -= 0.02 * run.tool_calls          # efficiency pressure
    r -= 0.10 * run.files_touched_outside_scope   # no collateral damage
    return max(r, 0.0)
```

This is worth writing and showing **even if the RL run does not finish during the hackathon.** It is the intellectual core of the pitch. See [`risks.md`](../03-build/risks.md) for how to present it honestly.

**Hard honesty rule:** do not claim a model was RL-trained in 4 hours. River's team is judging. Either start the run before the event, or run it on a toy problem so a few iterations visibly complete, and say plainly that the real run is overnight.

## 6. Who it is for

- **Primary:** any team running coding agents at volume with a real test suite. They feel the bill and the repetition immediately.
- **Secondary (QM's world):** an org with a fleet of agents, where one person's graduated model instantly serves everyone. Graduation compounds across the org.
- **Tertiary:** non-coding agents where a verifier exists (a browser agent that confirms a form submitted, an ops agent whose alert cleared).

## 7. What makes it a company and not a hack

- The data moat is generated by work customers already pay for.
- It gets cheaper the more it is used, which is the opposite of every rented-intelligence product.
- It is vendor-neutral by construction. The router speaks OpenAI-compatible, so it sits in front of anything.
- The asset is portable. Weights you own, unlike a cache entry that dies in five minutes or a vendor's memory feature that dies when you switch vendors.

## 8. Success criteria for Sunday

The demo is a win if all four are on screen:

1. A task type visibly graduating, live, from LEARNING to GRADUATED.
2. The same task run before and after, with **turns and tool calls** dropping and the result still verified.
3. Cost per task dropping, measured honestly against a **caching-enabled** frontier baseline.
4. A failure being caught by the verifier and escalated back to the frontier model, proving it is safe.

Point 4 matters more than people think. Showing the failure path is what separates a demo from a toy.

## 9. Naming

**GRADUATE** is the working name. The verb does the explaining: a task graduates from the expensive general model to your cheap specialist. Alternates if it clashes with anything at the event: `Tenure`, `Apprentice`, `Exit Zero`, `Alma`.
